## Goal

A CLIENT_ADMIN can configure outreach settings, pause everything, manage a suppression list, record
consent for a contact, and create an outreach plan for that contact. The plan is checked against policy,
stored as scheduled tasks, and claimed exactly once by a dispatcher that runs the ComplianceGate before
any (future) send. Every decision is traced and audited in a tamper-evident chain. Tenants are isolated
at the repository layer throughout.

## Decisions (locked for this sprint)

| # | Decision | Why |
|---|---|---|
| D1 | Plain typed state machine + Celery + transactional outbox; **no LangGraph** | ADR-001 |
| D2 | **US profile only.** Any other `region_profile` → gate blocks with `REGION_RULE` | Product decision Q1 |
| D3 | Default cadence: inbound = email +5 min → call +2 d → email +2 d; outbound = email d0 → call d2 → email d4; max 3 touches; min gap 48 h between touches (the first inbound email is exempt from the gap) | Product decision Q5 |
| D4 | Call window default 09:00–20:00 **contact-local**; email has no time window (cadence only) | compliance §3 |
| D5 | Call consent: latest `call` consent row must be `granted` with basis `express_written_consent`, **or** `express_consent` whose source is `widget`, `email_reply` or `call`. Email: latest `email` row `granted` with any basis (incl. `documented_lawful_basis`). Revocation beats an older grant | compliance §2 |
| D6 | Email/phone lookup reuses **`contact_identities`** (unique `(tenant_id, identity_type, identity_value)`), not new columns on `contacts`. New identity type `phone` (E.164); `email` values lower-cased | Code already has the table (`migrations/versions/0040_…`) |
| D7 | `to_e164` moves from `api/calls/voice.py` to `services/common/src/common/phone.py`; `calls` imports it from there (behaviour unchanged) | One normaliser for calls, imports, gate |
| D8 | LLM plan refinement is **out of scope** (default deterministic plan only). Tool calling on `LLMProvider` is out of scope (lands with A2's composer) | Keep A1 thin |
| D9 | The dispatcher only claims tasks whose channel has a **registered executor**. In A1 none are registered, so planned tasks stay `scheduled` (visible, never dropped) — the claim path is proven with a test-only executor | No silent drop, no fake sends |
| D10 | Audit becomes hash-chained by a **Beat sealer** (v1.1, was: in `record_audit`). `record_audit` stays one INSERT; `agents.seal_audit_chain` links unsealed rows per tenant under that tenant's `audit_chain_heads` row lock (`chain_seq`, `prev_hash`, `row_hash`). All rows get sealed, including pre-existing ones. Verify reports rows written since the last seal as `unsealed` | compliance / PHASE0 C3; in-transaction chaining would have put a lock + transaction on every one of ~40 existing `record_audit` callers and broken their stub-DB tests |
| D11 | Named Celery queues: `celery` (existing default), `agents`, `email`, `calls`; one worker consumes all (`-Q celery,agents,email,calls`). No concurrency change | RAM (PHASE0 §8) |

### A1.2 — ComplianceGate + kill switches + settings, consent & suppression APIs

**`agents/compliance.py`**

```python
@dataclass(frozen=True)
class GateResult:
    ok: bool
    code: str | None          # UPPER_SNAKE_CASE, None when ok
    detail: dict[str, Any]    # non-PII inputs that decided it (e.g. local_time, touches)

async def check(db, claims, *, contact_id: str, channel: Literal["email", "call"], now: datetime) -> GateResult
```

Order and codes exactly as `compliance.md` §1 (US only): `OUTREACH_PAUSED_PLATFORM`,
`OUTREACH_PAUSED_TENANT`, `CHANNEL_DISABLED`, `CONTACT_NOT_FOUND`, `CONTACT_SUPPRESSED`,
`NO_CONSENT` (D5), `CONTACT_TIMEZONE_UNKNOWN` (call only), `OUTSIDE_CALLING_WINDOW` (call only),
`CADENCE_LIMIT`, `MAX_TOUCHES`, `MAX_ATTEMPTS` (call), `COST_CAP_REACHED` (only when a cap is set),
`REGION_RULE`. Rules:
- kill switches read fresh from the DB every call (no cache);
- suppression checks the contact's normalised email (email channel) / phone (call channel) and `all`;
- window uses the contact's IANA timezone, computed with `zoneinfo` (DST-safe); end is exclusive;
- touches = completed tasks for the contact across plans in the last 365 days; gap = hours since the
  last completed task (any channel);
- every result is written as an `agent_tool_calls` row (tool = `compliance_gate`) inside the caller's
  `agent_run`, and **failures** also write an `audit_events` row (`action = 'outreach.gate_blocked'`).
- The gate **never** returns ok on an internal error: DB/lookup errors propagate (explicit failure).

**Admin API** (`agents/routes.py`, router prefix `/admin/outreach`, plus the existing tenant-scoped
pattern `/admin/tenants/{tenant_id}/outreach/...` for PLATFORM_ADMIN, copying
`admin/settings_routes.py:tenant_scoped_router`):

| Method + path | Roles | Notes |
|---|---|---|
| `GET /settings` | CLIENT_ADMIN, CLIENT_AGENT (read) | Defaults returned if no row (not persisted) |
| `PUT /settings` | CLIENT_ADMIN | Pydantic: channels ⊆ {email, call}; window start < end; timezone-free times; `region_profile` must be `US` (422 `REGION_UNSUPPORTED`) |
| `POST /pause` / `POST /resume` | CLIENT_ADMIN | Tenant kill switch; audited |
| `PUT /platform/pause` body `{paused: bool}` | PLATFORM_ADMIN only | Global kill switch; audited via `record_platform_audit` (A1.5) |
| `GET /suppressions?channel=&q=` | CLIENT_ADMIN, CLIENT_AGENT | Paged |
| `POST /suppressions` | CLIENT_ADMIN, CLIENT_AGENT | Value normalised server-side; duplicates → 200 idempotent |

### A1.3 — Outbox events + named queues

- `agents/events.py:emit(conn_or_db, claims, kind, payload, *, available_at=None)` — **must be called
  with the same connection/transaction as the caller's state change** (signature accepts the
  connection from `db.acquire()` + `conn.transaction()`; pattern used by `admin/repository.py:delete_own_tenant`).
  Allowed kinds (enum): `inbound_lead_created`, `outreach_requested`, `email_reply_received`,
  `email_bounced`, `email_complained`, `call_completed`, `meeting_booked`, `opt_out_received`,
  `human_takeover`. Unknown kind → `ValidationError`.
- `agents.dispatch_events` Celery task on queue `agents`, Beat every
  `AGENT_EVENT_DISPATCH_INTERVAL_SECONDS` (new setting, default 15): system-scoped claim
  (`UPDATE … SET status='processing', attempts=attempts+1 WHERE event_id IN (SELECT … WHERE status='pending'
  AND available_at <= now() ORDER BY available_at FOR UPDATE SKIP LOCKED LIMIT $1) RETURNING …`), then per
  event: build claims from the row's `tenant_id` → handler → `done`; handler error → back to `pending`
  with `available_at = now() + backoff(attempts) ± jitter`, or `failed` after 5 attempts (dead letter,
  logged `agent_event_dead_lettered`).
- **A1 handlers:** `outreach_requested` → planner (A1.4); `opt_out_received` / `human_takeover` /
  `meeting_booked` / `email_reply_received` → **stop conditions** (cancel the contact's active plan's
  non-terminal tasks, plan `stopped` with reason). The remaining kinds (`inbound_lead_created`,
  `email_bounced`, `email_complained`, `call_completed`) have **no handler in A1**, so `emit` rejects them
  with `ValidationError(EVENT_KIND_NOT_ENABLED)` — nothing can pile up unprocessed. Each is enabled in the
  sprint that adds its handler (A2–A6).
- Queues (D11): `celery_app.conf.task_routes = {"agents.*": {"queue": "agents"}, "email_agent.*": {"queue": "email"}, "call_agent.*": {"queue": "calls"}}`;
  `deploy/docker-compose.prod.yml` worker command adds `-Q celery,agents,email,calls`;
  `deploy/.env.example` documents the new settings. Existing tasks keep the default `celery` queue.

**Tests:** emit inside a rolled-back transaction leaves **no** event (outbox guarantee); two concurrent
dispatcher runs claim each event once; retry/backoff and dead-letter after 5; handler receives claims
for the row's tenant only; stop-condition handler cancels only that tenant's contact's tasks; task
routing table (a task named `agents.x` routes to `agents`).

### A1.4 — Planner, policy validator, plans/tasks, exactly-once task claim

- `agents/models.py`: `AgentTask`, `OutreachPlan` (Pydantic, as `agents.md` §2), `PolicyNote`.
- `agents/policy.py` (**pure**, no I/O): `validate(plan, settings, gate_inputs, now) -> (OutreachPlan | None, list[PolicyNote])`:
  drops steps for channels not enabled or without consent (D5); enforces the 48 h gap (except first
  inbound email), max touches; moves call steps to the next window opening in the contact's timezone
  (and drops them if the timezone is unknown); returns `None` + note `NO_ALLOWED_CHANNEL` if empty.
- `agents/planner.py`: `default_plan(kind, settings) -> OutreachPlan` (D3 cadences) → `policy.validate` →
  persist campaign (create-or-reuse per request), plan, tasks in **one transaction**;
  `idempotency_key = sha256(f"{plan_id}:{step_index}")`; at most one active plan per contact
  (unique index) — a second request returns `409 PLAN_ALREADY_ACTIVE`.
- Admin API: `POST /admin/outreach/contacts/{contact_id}/plans` body `{kind: "outbound_manual", goal}` →
  emits `outreach_requested` (outbox, same transaction as nothing else — the event *is* the request) and
  returns `202 {event_id}`; `GET /admin/outreach/contacts/{contact_id}/plan` → active plan + tasks + policy
  notes; `POST /admin/outreach/plans/{plan_id}:cancel` (CLIENT_ADMIN, owner agent).
- **Task dispatcher** `agents.dispatch_due_tasks` (queue `agents`, Beat every
  `AGENT_TASK_DISPATCH_INTERVAL_SECONDS`, default 30): system-scoped claim of `scheduled` tasks with
  `scheduled_at <= now()` **whose channel is in the executor registry** (D9) → `in_progress`,
  `claimed_at = now()` → open an `agent_run` → **gate** → if blocked: `cancelled` (permanent codes:
  suppressed, no consent, region) or back to `scheduled` at the next allowed time (window, cadence,
  pause — no attempt consumed) → else executor → `completed`/`failed` (+ retries as `agents.md` §4).
- **Reaper** `agents.reap_stale_tasks` (Beat, 5 min): `in_progress` older than
  `AGENT_TASK_LEASE_SECONDS` (default 600) → `scheduled` with `last_error='LEASE_EXPIRED'`.
- Executor registry: `agents/executors.py` — `register(channel, executor)`; empty in production code;
  tests register a recording executor.

**Tests:** policy property tests (Hypothesis or table-driven) — no output plan violates gap / touches /
window / consent for any input; planner idempotency (same request twice → 409, one plan); exactly-once
claim (two dispatchers concurrently, one executor call per task); gate-blocked paths (cancel vs
reschedule, attempts unchanged on reschedule); reaper; tasks for unregistered channels never claimed;
isolation (tenant A's dispatcher run never executes tenant B's task with A's claims — assert claims
rebuilt from the row).

### A1.5 — Tool registry, traces, hash-chained audit

- `agents/tools/__init__.py`: `Tool` protocol (`name`, `InputModel`, `OutputModel`, `write: bool`,
  `async def run(db, claims, args) -> output`); registry; `invoke(db, claims, run_id, tool, args)` validates
  input with Pydantic, runs, writes `agent_tool_calls` (args redacted: emails/phones replaced by
  `***@domain` / last-2-digits), writes `audit_events` for write tools, never swallows errors.
- Tools in A1 (read-only + one write): `search_knowledge` (wraps `rag.retrieve_hybrid`, returns
  passages + chunk ids + confidence; **no LLM generation in A1**), `get_contact` (contact + identities +
  latest consents per channel, no other tenant data), `log_activity` (write: timeline/lead activity via
  `leads.repository.add_activity` when the contact has a lead, else a contact timeline entry).
- `audit/repository.py:record_audit` becomes chained (D10): inside a transaction, `SELECT last_hash FROM
  audit_chain_heads WHERE tenant_id=$1 FOR UPDATE` (insert head if missing), `row_hash = sha256(prev_hash
  || canonical_json(row without hashes))`, insert row, update head. Canonical JSON = sorted keys, UTF-8,
  no whitespace.
  `audit_events.tenant_id` is `NOT NULL` and `record_audit` rejects global claims, so platform actions
  (the global kill switch) use a new `record_platform_audit(db, actor, action, ...)` that writes
  `tenant_id = '__platform__'` (reserved; a tenant can never get this id — `create_tenant_with_admin`
  generates uuid hex) and chains under the same head key. It is callable only from PLATFORM_ADMIN routes.
  `verify_audit_chain(db, claims) -> ChainReport(first_chained_at, rows_checked, broken_at|None)` +
  `GET /admin/audit/verify` (CLIENT_ADMIN own tenant) and `GET /admin/tenants/{tenant_id}/audit/verify`
  (PLATFORM_ADMIN, existing `tenant_scoped_router` in `audit/routes.py`).

```bash
curl -s -b cookies.txt -X PUT "$API/admin/outreach/settings" -H 'Content-Type: application/json' \
  -d '{"enabled_channels":["email","call"],"email_mode":"draft_for_review","region_profile":"US"}'
# 2. pick a contact you own; give it a timezone and email consent only
curl -s -b cookies.txt -X POST "$API/admin/outreach/contacts/$CONTACT/consents" -H 'Content-Type: application/json' \
  -d '{"channel":"email","status":"granted","basis":"documented_lawful_basis","source":"admin_form","wording":"Existing customer"}'
# 3. gate dry-runs: email → ok; call → NO_CONSENT
curl -s -b cookies.txt "$API/admin/outreach/contacts/$CONTACT/gate?channel=email"
curl -s -b cookies.txt "$API/admin/outreach/contacts/$CONTACT/gate?channel=call"
# 4. request a plan → 202; after ~15 s the plan shows email d0, email d4 (call dropped: no consent) + policy notes
curl -s -b cookies.txt -X POST "$API/admin/outreach/contacts/$CONTACT/plans" -H 'Content-Type: application/json' -d '{"kind":"outbound_manual","goal":"follow_up"}'
curl -s -b cookies.txt "$API/admin/outreach/contacts/$CONTACT/plan"
# 5. tasks stay "scheduled" (no executors in A1) — nothing is sent
# 6. pause → gate returns OUTREACH_PAUSED_TENANT; resume
curl -s -b cookies.txt -X POST "$API/admin/outreach/pause"; curl -s -b cookies.txt "$API/admin/outreach/contacts/$CONTACT/gate?channel=email"
curl -s -b cookies.txt -X POST "$API/admin/outreach/resume"
# 7. suppress the contact's email → gate CONTACT_SUPPRESSED; stop the plan
# 8. audit chain verifies
curl -s -b cookies.txt "$API/admin/audit/verify"
```

## Risks

| Risk | Mitigation |
|---|---|
| Email case-collisions block the migration | Fail loud with counts; a one-off merge script is written only if it happens |
| Audit chaining adds a row lock per tenant on every audit write | Single short transaction; measured in the real-DB check; head row per tenant (not global) |
| Beat cadence + claim queries on a small droplet | Partial indexes on due rows; `LIMIT` per tick (50) |

## As built (2026-10-15) — deviations from v1, all deliberate

| # | What changed | Why |
|---|---|---|
| B1 | Audit chain = Beat sealer (D10 above), `audit/chain.py`; migration adds `audit_events.chain_seq` + `audit_chain_heads.last_seq` | Zero change to existing audit writers; deletions are detectable via contiguous `chain_seq` |
| B2 | Gate order follows `compliance.md` §1: `REGION_RULE` before `COST_CAP_REACHED` | compliance.md is the parent doc |
| B3 | `MAX_ATTEMPTS` = sum of `attempts` on the contact's call tasks (365 d) ≥ `max_call_attempts`. A task's `attempts` increments only **after** the gate passes, so a gate deferral never consumes one | Spec left "attempts" undefined; this is the only reading where reschedules are free |
| B4 | Gate blocks split into **permanent** (task → `cancelled`): `CONTACT_NOT_FOUND`, `CONTACT_SUPPRESSED`, `NO_CONSENT`, `CONTACT_TIMEZONE_UNKNOWN`, `MAX_TOUCHES`, `MAX_ATTEMPTS`, `REGION_RULE`; and **deferrable** (task → `scheduled` at `retry_at`): pauses, `CHANNEL_DISABLED` (+1 h), window (next opening), cadence (last touch + gap), cost cap (1st of next month UTC) | Spec listed only three permanent codes; a call to a contact whose touch budget is spent can never become legal by waiting |
| B5 | The task claim skips tenants whose kill switch is on (the gate still re-checks) | A paused tenant would otherwise write an audit row per task per hour |
| B6 | `PLAN_ALREADY_ACTIVE` is `409` (`ConflictError`) | As specified; noted because the repository raises it too (race with the event handler) |
| B7 | Event handler errors: `AppException` with 4xx → dead-letter immediately (deterministic); anything else → backoff 30 s·2ⁿ ±20 %, dead-letter after 5. `processing` events past the lease are reaped back to `pending` | agents.md §4 retry rule; a worker dying mid-event must not strand it |
| B8 | Extra endpoint `GET /admin/outreach/events/{event_id}` → `{status, attempts, last_error}` | The 202 returns an `event_id`; without this a `NO_ALLOWED_CHANNEL` outcome was invisible |
| B9 | `log_activity` on a contact with no lead → `422 NO_LEAD` | There is no contact-level timeline table (the timeline is a read-only aggregate); added when a sprint needs it |
| B10 | Number-derived timezone is not implemented: a call to a contact without `timezone` blocks (`CONTACT_TIMEZONE_UNKNOWN`) | compliance.md's "else block" path; area-code mapping lands with CSV import (A5) |
| B11 | Migration backfill/lower-casing verified by `upgrade → downgrade 0065 → upgrade` on a real DB, not by an automated test with seeded collisions | Test harness migrates an empty DB; covered in the DoD real-DB check |
