# Sprint A7 — Calling Agent, inbound + warm transfer

> **Status:** IMPLEMENTED (awaiting review) · spec v1 · 2026-10-16 — see **As built** at the end
> **Parent docs:** [`../calling_agent.md`](../calling_agent.md) §2 (inbound), §4 · [`A6.md`](A6.md) · ADR-002
> **Outcome:** someone calls the client's Plivo number; Rebecca answers with the same disclosure, knows a
> returning contact by caller ID, answers from the knowledge base, books, takes "call me back tomorrow",
> honours "don't call me", and warm-transfers to the team with a spoken summary for the person who
> picks up. Unknown callers who engage become leads for the team.

## Decisions

| # | Decision | Why |
|---|---|---|
| N1 | **Number → tenant registry** `telephony_numbers(number_e164 PK, tenant_id, provider, active)`. Saving the call config registers its `from_number` for that tenant (a number another tenant holds → `409 NUMBER_IN_USE`; the old number of this tenant is released). This is the **only** claims-less lookup for inbound calls (PHASE0 §3) | One number reaches exactly one client |
| N2 | **Inbound webhooks** (static, set on a Plivo Application attached to the number): `POST /public/call-agent/inbound/answer` and `/inbound/hangup`. Tenant = registry lookup of the posted `To`; the request must then carry a valid `X-Plivo-Signature-V3` for **that** tenant's auth token (so a forged `To` can't pick a tenant). Unknown number / bad signature → the same 401. `inbound_enabled` (default on) can switch answering off (polite "please call back later" + hang up) | Tenant never from headers/body alone |
| N3 | **Caller ID → contact** (tenant-scoped phone identity). Known contact → greeting by first name and their history in the call context; unknown → "new caller" | calling_agent §2 |
| N4 | **Same script order as outbound:** "Hi{, Jane}, thanks for calling {company}. This is Rebecca, an AI assistant. This call is recorded for quality. How can I help?" — recording starts on the first turn, objection stops + deletes it. The A6 turn loop is reused unchanged except the customer's number is `From` (inbound) instead of `To` | One script, one set of rules |
| N5 | **"Call me back" on an inbound call** is express consent to be called by the AI (source `call`, A1 D5): recorded as call consent, and a call task is put on the contact's plan (an existing scheduled call moves; otherwise a call-only plan) for the next day, window-adjusted. Unknown caller or no timezone → team hand-off | calling_agent §4 |
| N6 | **Warm transfer (inbound and outbound):** `<Dial confirmSound=…>` — when the team member answers they first hear a code-built whisper ("Rebecca transferring a caller: Jane Doe. They asked about …"), then the caller is connected. Unanswered → "our team couldn't pick up, they'll call you back" + hand-off event | calling_agent §4; whisper summary |
| N7 | **Unknown callers who engaged** (≥ 1 caller turn) become a lead after the call (`source=inbound_call`, phone, summary on the timeline, feed event) so the team can follow up | No lost inbound lead |
| N8 | No concurrency cap on inbound (turn-based webhooks are light); outbound keeps its cap | A6 L9 |
| N9 | **Whisper attribute is unverified on a live line** (`confirmSound` per Plivo Dial docs) — confirm on the first real transfer | ADR-002 "measure, don't guess" |

## Data (migration 0072)
`telephony_numbers`; `tenant_call_agent_configs.inbound_enabled boolean NOT NULL DEFAULT true`.

## API
`GET /admin/outreach/call-config` adds `inbound_answer_url` / `inbound_hangup_url` (to paste into the Plivo
Application) and `inbound_enabled`; `PUT` accepts `inbound_enabled` and registers the number.

## Tests
Unit: whisper text, customer-number selection. Integration (real DB, Plivo faked, signed webhooks):
inbound answer greets a known contact by name; unknown number / wrong tenant's signature → 401; a second
tenant can't register the same number (409); "call me back tomorrow" records call consent + schedules a
call task for the next day; "don't call me" suppresses the caller's number; transfer XML carries the
whisper URL and the whisper names the caller and their question; unanswered transfer → hand-off; an
unknown caller who asked a question becomes a lead after hangup; inbound switched off → polite hang-up.

## As built (2026-10-16)

| # | Note |
|---|---|
| O1 | Bug found by the tests and fixed (affects A6 too): saving the call config **without** re-sending the auth token (meant to keep the stored one) failed with a NOT NULL error on an existing row. The kept token is now coalesced in the inserted row itself |
| O2 | The customer's number is `To` on outbound calls and `From` on inbound — opt-out / wrong-number suppression uses the right one |
| O3 | The whisper is built in code (caller name or "a new caller" + their last real question), never by the model |
| O4 | An unknown caller asking for a callback gets the team hand-off (no contact, no timezone = no AI callback) |
| O5 | `transfer_unanswered`, `callback_requested` and the other hand-offs all write `agent_call_needs_human` feed events |

**Plivo setup per client (once):** in the Plivo console create an Application with Answer URL =
`inbound_answer_url` and Hangup URL = `inbound_hangup_url` (both POST, shown by `GET /admin/outreach/call-config`),
then attach the client's number to it. Outbound calls need no Application (each call carries its own URLs).
