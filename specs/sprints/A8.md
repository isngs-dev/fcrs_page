> **Status:** IMPLEMENTED (awaiting review) · spec v1 · 2026-10-19 — see **As built** at the end
> **Parent docs:** [`../PHASE0_PLAN.md`](../PHASE0_PLAN.md) §6 (A8) · [`../email_agent.md`](../email_agent.md) §3 ·

> **Outcome:** a client's team runs Rebecca's email and calling agents from the console: they see what the
> agents did and what needs a person, review and approve email drafts, read call transcripts and play
> recordings, start outreach (CSV, one contact, or "Talk to Rebecca"), stop a campaign, manage
> settings / kill switch / do-not-contact list, and see a lead's agent activity in the lead drawer.

## Decisions

| # | Decision | Why |
|---|---|---|
| U1 | New sidebar group entry **Outreach** (CLIENT_ADMIN + CLIENT_AGENT) with children **Emails**, **Calls**, **Campaigns**, **Outreach settings** (CLIENT_ADMIN only) | One area for the agents, next to the existing tools |
| U2 | Same console patterns as every other surface: async server pages reading URL state, one `"use server"` lib (`lib/outreach.ts`) mapping snake_case → camelCase with `{status: "ok" \| "error"}` results, thin client components for forms/buttons, no `tenantId` (implicit routes only; PLATFORM_ADMIN reaches a tenant by switching chatbot) | Matches `lib/voice-calls.ts`, `lib/notifications.ts` |
| U3 | **Overview** page (`/outreach`): paused state (tenant + platform), enabled channels, email mode, drafts awaiting review, active plans, tasks due in 24 h, emails sent / calls / bookings in 7 days, and (admins only) this month's cost by kind vs the cap — one new endpoint `GET /admin/outreach/overview` | The "feed" in PHASE0 §6: what happened, what needs a person. Needs-a-person items already land in Notifications (`agent_*_needs_human`) — linked, not duplicated |
| U4 | **Emails** (`/outreach/emails`): filter pills Drafts / Sent / Received / Failed / All; a row opens a detail panel (`?email=`) with subject, body, classification/band/handled action, sources; drafts can be **edited, approved, discarded** (existing A2 endpoints) | email_agent §3 |
| U5 | **Calls** (`/outreach/calls`): list (direction, number, status, outcome, duration); detail (`?call=`) shows summary, outcome, transfer reason, the transcript turn by turn, and an audio player for the recording | calling_agent §5 |
| U6 | **Recording playback goes through our API**, never a Plivo URL in the browser: `GET /admin/outreach/calls/{id}/recording` fetches the mp3 server-side with the tenant's Plivo credentials and streams it; the admin-web route `/outreach/calls/{id}/recording` forwards the session cookie (same as the knowledge download route). Only `https://*.plivo.com` URLs are fetched (SSRF guard). No recording (objection, deleted, none) → 404 | Recording URLs are credentials-adjacent; keep tenant scoping + RBAC on playback |
| U7 | **Fix (RBAC):** `GET /calls` and `GET /calls/{id}` showed a CLIENT_AGENT every call in the tenant. Now an agent sees calls of contacts they can see (`contact_visible`); unmatched inbound calls (no contact) are admin-only — the same rule as emails | Found while building U5; tenant isolation was intact, role scoping wasn't |
| U8 | **Campaigns** (`/outreach/campaigns`): admins see campaigns (name, kind, created, plans active / stopped / completed) and can **Stop** one (stops every active plan in it, campaign → `cancelled`, audited) — `GET /admin/outreach/campaigns`, `POST /admin/outreach/campaigns/{id}:stop`. No "pause": nothing reads campaign status, so a pause would be dead config | A1 kill switch already pauses everything |
| U9 | Campaigns page also hosts the three A5 ways to start outreach (CLIENT_ADMIN + CLIENT_AGENT): **CSV import** (upload → preview with counts + rejected rows + download rejected CSV → consent attestation checkbox → commit or discard), **Add one contact**, **Talk to Rebecca** (text → confirm card with summary + sample → confirm / discard). Nothing launches without the explicit confirm step | A5 R-rules: unconfirmed never launches |
| U10 | **Outreach settings** (`/outreach/settings`, admin): agent settings form (channels, email mode, calling window, limits, cost cap in dollars, physical address, inbound automation), **Pause / Resume** button, email sender config (API key write-only, shows the two SendGrid URLs to paste), call config (Plivo auth token write-only, shows the inbound URLs to paste), and the do-not-contact list (search, add, remove) | All endpoints exist (A1/A2/A3/A6/A7) |
| U11 | Lead drawer gets an **"Agents"** tab: the lead's contact, the active plan with its steps, consents per channel, emails and calls for that contact, plus **Take over** (emits `human_takeover` → plan stops) — `GET /admin/outreach/leads/{lead_id}/activity`, `POST /admin/outreach/contacts/{contact_id}:takeover`. A lead with no contact yet → "No agent activity" | PHASE0 §6 "lead Agent activity tab"; email_agent §3 human takeover |
| U12 | Money is stored in micros; the UI shows dollars (2 decimals) and converts the cap on save | One unit in the DB |

## API (new)

| Method + path | Roles | Notes |
|---|---|---|
| `GET /admin/outreach/overview` | admin, agent | costs only for admins (`null` for agents) |
| `GET /admin/outreach/campaigns` | admin | newest first, with plan counts |
| `POST /admin/outreach/campaigns/{id}:stop` | admin | 404 for another tenant's id; audited |
| `GET /admin/outreach/leads/{lead_id}/activity` | admin, agent | agent: only a visible contact, else 404 |
| `POST /admin/outreach/contacts/{contact_id}:takeover` | admin, agent | stops the plan at once + emits `human_takeover`; `{event_id, tasks_cancelled}`; audited |
| `GET /admin/outreach/calls/{id}/recording` | admin, agent | `audio/mpeg`; U6 |

Each also mounts under `/admin/tenants/{tenant_id}/outreach` for PLATFORM_ADMIN, like A1–A7.

## Tests
Backend integration (real Postgres): overview counts + agent sees no costs; campaigns list counts + stop
stops only that campaign's plans + tenant B can't stop tenant A's campaign (404); lead activity returns
plan/consents/emails/calls for the lead's contact and 404 for an agent who can't see it; takeover stops
the plan via the outbox; calls list/detail hide other agents' calls from a CLIENT_AGENT; recording
streams through a faked provider, 404 when there's none, refuses a non-Plivo URL.
Admin-web (vitest): lib mappers + query builders, nav shows Outreach per role, email detail actions,
call transcript rendering, import preview → commit flow, settings form conversions (dollars ↔ micros,
HH:MM), lead Agents tab.
Browser walkthrough per role (CLIENT_ADMIN, CLIENT_AGENT) on the dev stack.
