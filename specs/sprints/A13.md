# Sprint A13 — Lead status, performance, exceptions

> **Status:** IMPLEMENTED (awaiting review) · spec v1 · 2026-10-21 — see **As built** at the end
> **Parent docs:** [`SCOPE-GAP-PLAN.md`](SCOPE-GAP-PLAN.md) (gap 5) · final scope §11 (admin dashboard and reporting),
> §9 "error queue", §14 #8 · [`A8.md`](A8.md) (Outreach area)
> **Outcome:** an admin sees where every lead Rebecca works on stands, how well outreach performs, and every
> failure, block or hand-off in one place — with retry where it makes sense.

## Decisions

| # | Decision | Why |
|---|---|---|
| R1 | **Outreach status per contact** (contacts with at least one plan), derived on read in this priority: **opted out** (unsubscribe/stop/do-not-call/complaint), **not interested**, **meeting booked**, **human handoff** (taken over, a reply handed to a person, a call escalated), **invalid contact** (bounced address / wrong number and no plan running), **qualified** (lead stage qualified/converted), **engaged** (replied or spoke on a call), **contacted** (a step completed), **new** | Scope §11 lead overview — exactly its nine states; derived, so it can never drift from the facts |
| R2 | **Performance** for a period (default 30 days; contacts whose first plan started in it): leads, contacted, **response time** (median minutes from plan start to the first completed step), **reply rate** (replied ÷ emailed), **lead → meeting** (booked ÷ leads), **show rate** (attended ÷ meetings with an outcome), **bounce / complaint / opt-out rate** (÷ e-mails sent), **call connection rate** (answered by a person ÷ calls placed), **cost per lead / per meeting** (admins only) | Scope §11 performance |
| R3 | **Meeting outcome**: past meetings can be marked **attended** or **no-show** (existing `completed` / `no_show` statuses, which the bookings report already counts but nothing set). Admins, or the agent assigned to that lead | Needed for show rate |
| R4 | **Exceptions** (admin): failed steps (with their error code) → **Retry** (back to scheduled now, attempts reset) or **Dismiss**; dead-lettered outbox events → **Retry**; actions blocked by the compliance gate in the last 7 days, counted by reason; escalated steps (e.g. no answer in the knowledge base, unstated commitment); counts + links for hand-offs (Notifications) and the intake queue | Scope §11 quality & reliability, §9 error queue |
| R5 | Console: Outreach → **Lead status** (status pills with counts + list), **Performance** (period selector, metric cards, meetings to mark), **Exceptions**. Status list and exceptions are admin-only (they name people); performance is for admins and agents (aggregates; cost only for admins) | Same RBAC rules as A8 |

No migration.

## API
`GET /admin/outreach/statuses?status=&limit=&offset=` (admin) · `GET /admin/outreach/performance?days=` (admin, agent) ·
`POST /admin/outreach/meetings/{event_id}:outcome {"outcome": "attended"|"no_show"}` (admin, or the lead's agent) ·
`GET /admin/outreach/exceptions` · `POST /admin/outreach/tasks/{id}:retry|:dismiss` · `POST /admin/outreach/events/{id}:retry` (admin).

## Tests
Integration: each status is reached by its fact and the priority holds; metrics on a seeded tenant (exact numbers);
attended/no-show set + show rate; agent can mark only their lead's meeting; exceptions list a failed step and a
dead event, retry puts them back to work; blocked counts by reason; tenant B sees none of A; RBAC per endpoint.

## As built (2026-10-21)

| # | Note |
|---|---|
| O1 | `agents/reporting.py`: one SQL query derives the status (R1) from suppressions, plans, bookings, hand-offs, lead stage, replies/caller turns and completed steps. "Opted out" and "invalid contact" apply only when no plan is still running (someone who said "no calls" but still gets e-mail isn't opted out) |
| O2 | Performance (R2) cohort = contacts whose **first** plan started in the period; e-mail rates are over e-mails sent in the period; call connection excludes voicemail/no-answer/machine |
| O3 | Meeting outcome (R3) reuses the existing `completed` / `no_show` statuses (the bookings report already counted them; nothing could set them before). Only meetings that have started can be marked |
| O4 | Retrying a failed **e-mail** step also puts its failed message back to `approved`, so it is resent (same Message-ID) instead of failing again; a step whose plan has ended can't be retried (`PLAN_NOT_ACTIVE`) |
| O5 | Blocked actions come from the gate's own traces (`agent_tool_calls`, tool `compliance_gate`), so the count is exact |
| O6 | Console: Outreach → **Lead status** (admin), **Performance** (admin + agent; cost for admins), **Exceptions** (admin). Browser-checked on the demo stack |

No migration.
