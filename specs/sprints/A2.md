# Sprint A2 — Email Agent, outbound (grounded composer, sender, unsubscribe, approval, write-back)

> **Status:** IMPLEMENTED (awaiting review) · spec v1.1 · 2026-10-15 — see **As built** at the end
> **Parent docs:** [`../email_agent.md`](../email_agent.md) §1 · [`../compliance.md`](../compliance.md) ·
> [`A1.md`](A1.md) (gate, plans, executor registry) · [`../PHASE0_PLAN.md`](../PHASE0_PLAN.md) §3/§7
> **Skills to load first:** `guardrails`, `platform-foundations`, `notification-service`, `llm-provider`,
> `rag-retrieval`, `scheduling-service`.
> **Outcome:** an `email` task claimed by the A1 dispatcher becomes a grounded, branded email. It is either
> sent (`auto_send`) or held as a draft in a review queue (`draft_for_review`, the default) that an
> admin approves, edits or discards. Headers are correct for threading and one-click unsubscribe.
> Unsubscribing suppresses the address and stops the plan. Each send is logged on the CRM timeline.

## Decisions

| # | Decision | Why |
|---|---|---|
| E1 | **Per-tenant sender, no platform default.** New table `tenant_email_agent_configs`: provider `sendgrid` (API key AES-GCM encrypted via `SecretBox`) or `smtp` (reuses the tenant's own `tenant_notification_configs` email row, never `PLATFORM_SMTP_*`). | Brief; PHASE0 C2 |
| E2 | `TransactionalEmailProvider` Protocol: `send(OutboundEmail) -> SentRef`. Two implementations: `SendGridEmailProvider` (httpx → `POST /v3/mail/send`, `X-Message-Id` captured) and `SmtpAgentEmailProvider` (stdlib smtplib with our headers). 4xx (except 429) → `EmailDeliveryError` (deterministic, `ValidationError` subtype); 429/5xx/timeouts → transient (task retried). | email_agent §1.5; same split as `notifications/providers.py` |
| E3 | **Threading:** one `email_threads` row per plan. The first email gets our `Message-ID` `<{uuid}@{from-domain}>`; later emails in the plan set `In-Reply-To` and `References` and use `Re: <first subject>`. | Replies land in one conversation |
| E4 | **Unsubscribe:** HMAC-SHA256 token over `v1.{tenant_id}.{contact_id}.{email_lower}` with `EMAIL_LINK_SECRET`. It doesn't expire (CAN-SPAM requires ≥ 30 days) and is single-purpose (the prefix differs from any other token). `List-Unsubscribe: <https://…/public/email/unsubscribe/{token}>` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click` (RFC 8058). `GET` shows a confirm page; `POST` (one-click or the button) suppresses and stops the plan. No `mailto:` until inbound email (A3). | Gmail/Yahoo bulk-sender rules; link scanners must not unsubscribe on GET |
| E5 | **Footer is mandatory:** AI disclosure ("— Rebecca, AI assistant for {company}"), the tenant's `physical_address` (agent_settings) and the unsubscribe URL. A missing address or link secret → `EMAIL_NOT_READY` (task `failed`, and `PUT /settings` refuses to enable `email`). | CAN-SPAM; FTC AI-disclosure guidance |
| E6 | **Grounded composer.** Retrieve with `retrieve_hybrid(goal intent + conversation summary)`. The LLM gets the same grounding rules as chat (only facts in the Context; `NO_ANSWER_FOUND` sentinel when it can't). Bands for outbound: **answer** = composed from context; **no context** = a short follow-up that states no facts (still allowed); **escalate** = sentinel, guardrail hit (`scan_output`) or a commitment check failure → no AI email, task `escalated`. The *clarify* band applies to replies (A3), not outbound. | email_agent §1.2; no invented answers |
| E7 | **Commitment check:** every currency amount, percentage and "free/discount/guarantee/refund" claim in the output must appear in the retrieved context; otherwise escalate. | "No unstated price/discount/commitment" |
| E8 | **Approval mode** `draft_for_review` (default): message saved `draft`, task parked in `pending` (= awaiting a human; neither claimed nor reaped). Approve → **gate re-run** → send → task `completed`. Edit is allowed while `draft`. Discard → task `cancelled`. Drafts older than `EMAIL_DRAFT_TTL_DAYS` (7) expire on the reaper tick (task `cancelled`, `DRAFT_EXPIRED`). `auto_send` sends inside the executor. | email_agent §1.4 |
| E9 | **Booking link:** the tenant's Calendly `scheduling_url` when configured, else `booking_url` from the email config, else the line "Just reply to this email and we'll find a time that suits you." (replies reach the `reply_to` human inbox until A3). Listing open native slots in the body and a signed standalone booking page are **deferred** (after A3). | email_agent §1.2 "decision in A2 spec" |
| E10 | **Stop on booking:** native and Calendly bookings resolve the contact by email identity and emit `meeting_booked`, so the A1 handler stops the plan. Emitted right after the booking insert, failure logged, never failing the booking. | A1 handler exists; a booked contact must not get more follow-ups |
| E11 | **Idempotency:** one `email_messages` row per task (`UNIQUE (tenant_id, task_id)`). Status walks `draft → approved → sending → sent \| failed`. A retry after `sending` re-sends with the **same** `Message-ID` (at-least-once; mail clients collapse duplicate Message-IDs). | SendGrid has no idempotency key |
| E12 | **CRM write-back:** `log_activity` (A1 tool, audited) with type `agent_email_sent` on the contact's lead. Contacts without a lead are skipped (`NO_LEAD`, A1 B9). One `usage_costs` row per send (`kind=email`, `EMAIL_COST_MICROS`, default 0). | email_agent §1.6 |
| E13 | Email steps of the default plan get `max_attempts = 3` (transient provider errors retry with backoff). | A1 default of 1 would fail on one timeout |

## Slices

### A2.1 — Migration 0067 + email config + providers
```sql
CREATE TABLE tenant_email_agent_configs (
  tenant_id text PRIMARY KEY, provider text NOT NULL CHECK (provider IN ('sendgrid','smtp')),
  from_address text NOT NULL, from_name text NULL, reply_to text NULL, booking_url text NULL,
  api_key_ciphertext text NULL, enabled boolean NOT NULL DEFAULT true,
  updated_at timestamptz NOT NULL DEFAULT now(), updated_by text NULL);
CREATE TABLE email_threads (
  tenant_id text NOT NULL, thread_id text NOT NULL, contact_id text NOT NULL, plan_id text NULL,
  subject text NOT NULL, status text NOT NULL DEFAULT 'open' CHECK (status IN ('open','closed')),
  last_message_at timestamptz NULL, created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, thread_id),
  FOREIGN KEY (tenant_id, contact_id) REFERENCES contacts (tenant_id, contact_id) ON DELETE CASCADE);
CREATE UNIQUE INDEX uq_email_threads_plan ON email_threads (tenant_id, plan_id) WHERE plan_id IS NOT NULL;
CREATE TABLE email_messages (
  tenant_id text NOT NULL, message_id text NOT NULL, thread_id text NOT NULL,
  direction text NOT NULL CHECK (direction IN ('outbound','inbound')),
  rfc_message_id text NOT NULL, in_reply_to text NULL, "references" text[] NULL,
  provider text NULL, provider_message_id text NULL,
  from_addr text NOT NULL, to_addr text NOT NULL, subject text NOT NULL,
  body_text text NOT NULL, body_html text NULL,
  status text NOT NULL CHECK (status IN ('draft','approved','sending','sent','failed','discarded','received')),
  band text NULL, sources jsonb NOT NULL DEFAULT '[]', task_id text NULL, last_error text NULL,
  approved_by text NULL, created_at timestamptz NOT NULL DEFAULT now(), sent_at timestamptz NULL,
  PRIMARY KEY (tenant_id, message_id),
  FOREIGN KEY (tenant_id, thread_id) REFERENCES email_threads (tenant_id, thread_id) ON DELETE CASCADE,
  UNIQUE (tenant_id, rfc_message_id));
CREATE UNIQUE INDEX uq_email_messages_task ON email_messages (tenant_id, task_id) WHERE task_id IS NOT NULL;
CREATE INDEX ix_email_messages_status ON email_messages (tenant_id, status, created_at DESC);
```
API: `GET/PUT /admin/outreach/email-config` (CLIENT_ADMIN; GET for CLIENT_AGENT; key write-only →
`has_api_key`; audited) + tenant-scoped variant. `PUT /settings` with `email` enabled requires an
enabled config, `physical_address` and `EMAIL_LINK_SECRET` → else 422 `EMAIL_NOT_READY`.

### A2.2 — Unsubscribe
`email_agent/links.py` (sign/verify, constant-time). Public routes `GET|POST /public/email/unsubscribe/{token}`:
tenant + contact come only from the verified token; `POST` → `add_suppression(email, unsubscribe)`,
`emit(opt_out_received)` + audit, idempotent; bad token → 404 page (no detail).

### A2.3 — Composer
`email_agent/composer.py`: `compose(db, claims, task, contact, settings, config) -> Composed(subject, body_text,
band, sources)`. Prompt = grounding rules + email rules (≤ 150 words, plain, one call to action, no
promises, AI disclosure is appended by code, not the model) + `Context:` block + task goal/intent +
contact first name + conversation summary (latest conversation of the contact's lead, if any). Output
format `SUBJECT: …\n\n<body>`. `scan_output` + commitment check (E7). Footer is appended by code (E5).

### A2.4 — Executor, approval API, write-back
`email_agent/executor.py` registered for `email` on import of `api.email_agent` (imported by the Celery
worker and the app). Admin API under `/admin/outreach/emails`: `GET ?status=` (list), `GET /{id}`,
`PUT /{id}` (edit draft), `POST /{id}:approve`, `POST /{id}:discard` — CLIENT_ADMIN and CLIENT_AGENT
(own contacts, 404 otherwise) + tenant-scoped variant.

### A2.5 — Stop on booking (E10)
Native `POST /public/schedule/book` and Calendly ingest → `contacts.get_contact_id_by_identity(email)` →
`emit(meeting_booked)`.

## Tests
Unit: token sign/verify/tamper/cross-tenant; header building (SendGrid payload + SMTP message: Message-ID,
In-Reply-To, References, List-Unsubscribe(-Post), Reply-To); commitment check table; composer bands with a
fake LLM (answer / no-context / sentinel → escalate / guardrail → escalate / unstated price → escalate);
SendGrid 2xx/4xx/429/5xx mapping (httpx MockTransport). Integration (real DB): executor auto_send →
`sent` + activity + cost + task completed; draft → task `pending` → approve (gate re-run) → sent;
approve blocked by a new suppression → not sent; discard; draft expiry; retry after `sending` reuses the
Message-ID; second email of the plan threads under the first; unsubscribe POST suppresses + stops plan
and is tenant-bound; RBAC + isolation on every route; booking emits `meeting_booked`.

## Manual recipe (after A1's)
```bash
curl -s -b cookies.txt -X PUT "$API/admin/outreach/email-config" -H 'Content-Type: application/json' \
  -d '{"provider":"sendgrid","from_address":"rebecca@mail.client.com","from_name":"Acme","reply_to":"sales@client.com","api_key":"<sendgrid key>"}'
curl -s -b cookies.txt -X PUT "$API/admin/outreach/settings" -H 'Content-Type: application/json' \
  -d '{"enabled_channels":["email"],"email_mode":"draft_for_review","physical_address":"1 Main St, Miami FL 33101"}'
# request a plan (A1 recipe step 4); within ~45 s a draft appears:
curl -s -b cookies.txt "$API/admin/outreach/emails?status=draft"
curl -s -b cookies.txt -X POST "$API/admin/outreach/emails/$MSG:approve"
# the mail arrives; its List-Unsubscribe one-click suppresses the address and stops the plan
```
Server: `EMAIL_LINK_SECRET` (≥ 32 chars) in `.env`, `alembic upgrade head` (0067), recreate api + worker + beat.
