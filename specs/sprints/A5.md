# Sprint A5 — Outbound feeding (add contact, CSV import, "Talk to Rebecca")

> **Status:** IMPLEMENTED (awaiting review) · spec v1 · 2026-10-16 — see **As built** at the end
> **Parent docs:** [`../PHASE0_PLAN.md`](../PHASE0_PLAN.md) A5 row · [`../compliance.md`](../compliance.md) §2 ·
> [`A1.md`](A1.md) (planner, gate, campaigns) · [`A4.md`](A4.md) (consent records)
> **Outcome:** a CLIENT_ADMIN or CLIENT_AGENT can (1) add one person and start outreach, (2) upload a
> CSV, see a preview with rejected rows and reasons, then commit it into one campaign of plans, and
> (3) type a request to Rebecca ("follow up with everyone from last week's upload by email"), see a
> confirm card, and only on confirm does anything launch. Calls only ever reach rows with genuine,
> attested consent evidence.

## Decisions

| # | Decision | Why |
|---|---|---|
| J1 | **Preview, then commit.** Upload parses and validates into an `outreach_imports` row (status `preview`) with a per-row report; nothing touches contacts/plans until `:commit`. `:discard` drops it. After commit or discard the stored row data is cleared (only the report counts stay) | PHASE0 demo; PII minimisation |
| J2 | **Columns** (header names case/space/underscore-insensitive): `name` (or `first_name` + `last_name`), `email`, `phone`, `timezone`, `call_consent`, `consent_date`, `consent_source`, `consent_wording`, `consent_type` (`express_written` default \| `express`). Unknown columns ignored and listed in the preview. UTF-8 (BOM ok), comma or semicolon, ≤ 2 MB, ≤ 5 000 rows | compliance §2.1 |
| J3 | **Row rules → rejected with reasons:** neither email nor phone (`NO_CONTACT_DETAILS`); bad email (`INVALID_EMAIL`); undialable phone (`INVALID_PHONE`); bad timezone (`INVALID_TIMEZONE`); same email/phone earlier in the file (`DUPLICATE_IN_FILE`); on the suppression list (`SUPPRESSED`). A row that claims `call_consent` but lacks phone, date (ISO, not in the future) or source is **imported without call consent** with warning `CALL_CONSENT_INCOMPLETE` | Bad data never silently lost; incomplete evidence never becomes consent |
| J4 | **De-dupe against the tenant:** a row whose email or phone already belongs to a contact **reuses** that contact (counted as `existing`), never a duplicate. Email lower-cased, phone E.164 (A1 D6) | PHASE0 "de-dupe by email_lower/phone_e164" |
| J5 | **Consent records on commit:** every row with an email gets email basis `documented_lawful_basis` (source `csv`, CAN-SPAM); rows with complete call evidence get call consent (`express_written_consent`, or `express_consent` when `consent_type=express` — which A1 D5 does **not** accept for AI calls). Evidence: `import_id`, row number, date, source, wording | compliance §2.1–2.3 |
| J6 | **Attestation:** committing a file with any call-consent row requires `consent_attested: true` ("I confirm this consent evidence is genuine"); else 422 `CONSENT_ATTESTATION_REQUIRED`. Audited with who attested | compliance §2.5 |
| J7 | **DNC flag:** the preview counts phone rows without written call consent as `needs_dnc_scrub` (informational; the AI never calls them anyway) | compliance §2.4 |
| J8 | **One campaign per import / command**, kind `outbound_csv` / `outbound_manual`; `planner.create_plan` gains optional `campaign_id` and `channels` (restricts the default plan to those channels). A contact with an active plan is skipped (`PLAN_ALREADY_ACTIVE`, counted) | One campaign = one thing the user launched |
| J9 | **Add one contact** = `POST /admin/outreach/contacts:add` — the same row rules (J3–J5) on one JSON row, optional `start_outreach`. Call evidence via this form also needs `consent_attested` | "Form" in PHASE0; one code path |
| J10 | **Talk to Rebecca:** `POST /admin/outreach/commands {text}` → tenant LLM returns JSON parsed into a closed schema (`action: start_outreach \| stop_outreach`, `audience`: emails / names / `created_within_days` / `last_import`, `channels`, `goal`). **Our code** resolves the audience (tenant-scoped, ≤ 500) and stores an `outreach_command_drafts` row (`pending`) with the resolved contacts; the reply is a confirm card (summary, count, sample names, channels). `:confirm` launches (one campaign); `:discard` drops. Unparseable → 422 `COMMAND_NOT_UNDERSTOOD`. The LLM never chooses contacts directly and nothing launches unconfirmed | PHASE0 "unconfirmed parse never launches"; prompt injection |
| J11 | Rejected rows download as CSV with formula-injection escaping (`common.csv_safe.escape_csv_cell`) | PHASE0 "formula-injection safe" |
| J12 | **Cancel-on-reply / sequences:** already in place (A1 plans, A3 reply stops the plan) — no new work | |

## Data (migration 0070)
`outreach_imports(tenant_id, import_id PK, status preview|committed|discarded, filename, campaign_name,
goal, rows jsonb, report jsonb, consent_attested bool, attested_by, created_by, created_at, committed_at)`;
`outreach_command_drafts(tenant_id, draft_id PK, raw_text, parsed jsonb, contact_ids text[],
status pending|confirmed|discarded, created_by, created_at, decided_at)`.

## API (`/admin/outreach`, CLIENT_ADMIN + CLIENT_AGENT; PLATFORM_ADMIN via the tenant-scoped router)
`POST /imports` (multipart `file`, `campaign_name`, `goal`) · `GET /imports/{id}` · `GET /imports/{id}/rejected.csv`
· `POST /imports/{id}:commit` (`{consent_attested}`) · `POST /imports/{id}:discard` · `POST /contacts:add`
· `POST /commands` · `GET /commands/{id}` · `POST /commands/{id}:confirm` · `POST /commands/{id}:discard`.

## Tests
Unit: header mapping, every row rule, duplicate-in-file, consent completeness, BOM/semicolon, size/row
limits, rejected.csv escaping, command schema (garbage / extra fields / unknown action rejected).
Integration (real DB): CSV of 20 → preview 17 valid / 3 rejected → commit → contacts + identities +
consents + one campaign of plans; existing contact reused; attestation required; express-only call
consent doesn't allow calls (plan has no call step); re-commit refused; tenant isolation (tenant B can't
read/commit A's import or draft); RBAC (VISITOR 403); command → draft → only confirm launches; injected
text in a command can't select another tenant's contacts.

## As built (2026-10-16)

| # | Note |
|---|---|
| K1 | Preview also rejects rows already on the suppression list (`SUPPRESSED`), and reports `existing` vs `new` contacts before anything is written |
| K2 | Commit claims the import with a compare-and-set (`preview → committed`), so two clicks can never import twice; a second commit gets `409 IMPORT_NOT_PREVIEW` |
| K3 | `rejected.csv` is available only while the import is a preview (the original cells are cleared on commit/discard) |
| K4 | A CLIENT_AGENT's imported/added contacts get `owner_agent_id` = that agent; their "Talk to Rebecca" requests only resolve to contacts they can see |
| K5 | The audience search lives in `contacts.repository.find_contacts` (module seam), matching email identities, exact names, `created_since`, or the last committed import |
| K6 | `start_outreach: false` on commit/add stores contacts and consents without creating plans |
